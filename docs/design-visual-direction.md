# TP QR 视觉方向与素材边界

TP QR 的产品视觉是“二维码发布档案系统”：近黑舞台、暖纸张、钴蓝校准线、青绿色发布状态和切角档案卡。视觉参考只用于确定布局、颜色、字体层级和交互节奏，运行时页面由 React、CSS、SVG 和真实数据重建。

## 代码原生实现

- 纸张、切角、撕边、校准线和状态印章使用 CSS/SVG，不把文字或按钮烘焙进图片。
- 二维码由 `qr-code-styling` 根据当前 slug 和渲染配置实时生成；预览、PNG/SVG/WEBP/JPG 下载共用同一套配置。
- 七类公共内容使用同一个阅读框架：图片、视频、音频、文件、网址、名片、文字分别渲染，同时保持统一的标题、状态和分享操作。
- 图表、版本列表、上传状态、错误提示和移动端 Drawer 全部来自 API/组件状态，概念图里的示例数字不进入产品。

## 响应式规则

- 桌面端以 1440×900 为主要工作台视口，编辑器使用“控制面板 + 纸张预览”双栏布局。
- 390×844 和 375×812 使用单列布局；表格只在局部容器横向滚动，页面根节点不得横向溢出。
- 所有按钮和菜单触控区域至少 44px；菜单支持点击外部和 Escape 关闭；`prefers-reduced-motion` 时不播放位移动效。
- 公共扫码页不显示后台导航、不要求登录，媒体加载失败时显示可恢复的错误状态。

## 可复现素材策略

公开仓库不提交无明确许可证的 ImageGen 位图、参考图、提示词或个人上传内容。纸张纹理和演示占位图由 `apps/web/src/lib/assets.ts` 内的自有 SVG 数据生成；测试媒体由 `npm run test:fixtures` 在 `tmp/fixtures/` 中确定性生成，目录被 Git 忽略。

运行时用户上传的图片、视频、音频和文件只经 Worker 写入私有 R2，公共页面通过 slug + 已发布版本的授权代理读取，不公开 bucket 或 object key。

## 内容结构

每种内容都有独立编辑字段，但公共页统一展示标题和发布状态：

| 类型 | 编辑重点 | 公共操作 |
| --- | --- | --- |
| 图片 | 文件、替代文本、标题 | 查看、保存、分享 |
| 视频 | 文件、封面、自动播放/循环 | 播放、全屏、下载 |
| 音频 | 文件、封面、标题、艺术家 | 播放、分享 |
| 文件 | 文件、显示名、描述 | 类型/大小、下载 |
| 网址 | HTTPS 地址、标题、描述 | 安全打开、复制 |
| 名片 | 姓名、组织、电话、邮箱、地址 | 保存 vCard、分享 |
| 文字 | 标题、正文 | 复制、分享 |

旧项目 API 和旧 D1 表仍保留兼容读取，方便迁移历史数据；它们不再出现在新的工作台导航或公共响应中，也不作为七类活码的运行时素材。
